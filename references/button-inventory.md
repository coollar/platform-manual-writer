# 按钮穷举手册

手册里漏得最多、错得最狠的，永远是**按钮**——尤其是"看不见的那些"。本文件定义"把一个页面上的按钮全部翻出来、记清楚"的标准动作。

> 一句话原则：**页面上凡是能点的，都要点一遍、记一笔。** 没列进清单的按钮，就不会进手册，也进不了复查断言——它会成为读者踩到的暗坑。

## 一、为什么必须穷举

**漏写的按钮有固定规律——全是"不显眼"的：**

| 类型 | 为什么漏 | 真实案例 |
|---|---|---|
| **无文字纯图标按钮** | 截图上看不出是什么，作者不敢写就跳过 | 「创建副本」图标：操作列**最左侧**、**三种状态都有**、悬停才出提示。手册原写"行末、仅已发布"——**两处都错** |
| **悬停才出现的** | 默认不可见，静态看页面根本发现不了 | 行内操作按钮常在 hover 时才渲染 |
| **藏在菜单里的** | 要点开「…」或右键才展开 | 项目卡片菜单 = 查看详情 / 编辑 / 关闭 / 归档(禁用) / 删除(禁用) |
| **只在某些状态下出现的** | 作者只看了手边那条数据 | 方案三态：草稿=编辑/发布/删除；已发布=查看/片段标注配置/创建任务/归档；**已归档=查看/片段标注配置/删除**（漏了第三态） |
| **禁用态的** | 灰掉的按钮最容易被当成"不存在" | 读者会问"为什么我的不能点"，手册必须解释禁用条件 |
| **抽屉 / 弹窗底部的** | 探查时只 dump 了字段，没记按钮 | 底部按钮文案常带空格：「确 定」「删 除」 |
| **折叠区 / Tab 内的** | 没展开就看不到 | 筛选区「展开 ∨」后又多出一排按钮 |

**结论**：凭截图写手册，一定漏按钮。**必须逐个点开看**。

## 二、清点范围：一个页面扫哪些位置

一个列表页，至少要扫这 9 处。**漏一处就是一整类按钮的缺失**。

| # | 位置 | 典型元素 |
|---|---|---|
| 1 | 页面**右上角主按钮** | 【新建】等入口 |
| 2 | **搜索 / 筛选区** | 【查询】【重置】【展开 ∨】（展开后还有内容） |
| 3 | 表格**行首** | 复选框、可选中的对象名（点开进详情） |
| 4 | **操作列** | 每个状态各扫一遍，**逐态分别记录** |
| 5 | 操作列里的**无文字图标按钮** | 逐个 hover 拿提示文本 |
| 6 | 卡片列表的**「…」菜单** | 点开 dump 菜单项 + **禁用态** |
| 7 | **Tab 栏** | 不同 Tab 内是完全不同的按钮集，每个 Tab 都要扫 |
| 8 | **抽屉 / 弹窗内部与底部** | 【确 定】【取 消】【保存】【添加一行】 |
| 9 | **分页区 / 列表工具条** | 每页条数、刷新、列设置、导出 |

**跨状态优先**：任何"某状态才有 / 三种状态都有"的说法，都必须**把对象推到每个状态各扫一遍**，不能拿一条现成数据推断。

## 三、每个按钮记什么

一个按钮一条记录，字段固定。缺字段就等于没记清。

| 字段 | 说明 |
|---|---|
| **位置** | 页面 → 区域（右上角 / 筛选区 / 操作列 / 卡片菜单 / 抽屉底部） |
| **文案 or 图标** | 有文字写文字（**照抄，含空格**）；无文字写图标形状 + **悬停提示** |
| **出现于哪些状态** | 草稿 / 已发布 / 已归档…（逐态列） |
| **是否禁用** | 灰态？禁用条件是什么？ |
| **点击结果** | 打开抽屉 / 打开弹窗 / 出二次确认 / **直接执行** / 展开下拉菜单 |
| **二次确认** | 有 / 无；**有则抄下确认框原文** |
| **可逆性** | 能否撤销 / 有无反向入口（如"取消发布"） |
| **前置条件** | 需要满足什么才能点（内容已锁定？数据非空？） |
| **危险级** | 只读可探 / 需授权写 / **禁点** |
| **证据** | 截图编号 / DOM dump |

## 四、点击分级：能点到什么程度

**不是所有按钮都能随便点。** 按危险级三档处理：

| 级别 | 对象 | 动作 |
|---|---|---|
| **只读级** | 打开抽屉、弹窗、下拉、菜单、切 Tab | **随便点**，点完关掉即可（关下拉别按 Esc，见 `probe-playbook.md`） |
| **可逆写级** | 新建 / 保存 / 编辑 / 删除**自建对象** | **获得授权后**做闭环：新建 → 保存 → 验证 → 观察 → 删除 → 复查消失 |
| **高危级** | 发布 / 启用 / 停用 / 归档 / 转码 / 重新质检 | **先判定交互形态再决定**（见下节）；**绝不在真实业务对象上试** |

> ⚠️ 「停用 / 归档」这类**可能无二次确认、点下即生效**的按钮是雷区。见 `probe-playbook.md` 的事故记录。

## 五、无文字图标按钮怎么认

这类按钮最容易漏，也最需要交代清楚。**四种手段，从省事到彻底**：

1. **扫 DOM** —— 用 `scripts/inventory_buttons.js` 自动列出页面上所有 `button / a / [role=button] / .anticon`，含无文字的那些。
2. **悬停读提示** —— 脚本对无文字图标逐个 hover，等 `.ant-tooltip` 出现后 dump 文本（如「创建副本」）。
3. **点开看结果**（只读级）—— 打开抽屉/弹窗，用**标题和字段**反推它的作用。
4. **读前端 bundle**（进阶）—— icon 组件名常能对上语义（`CopyOutlined` → 副本）。

**铁律：不要靠图标形状猜含义。** 同一平台不同页面的同形图标含义可能不同；`⋯` 在不同列表里可能是"更多操作"也可能是"更多信息"。**必须 hover 看提示或点开看结果。**

## 六、高危按钮：不点也能判定二次确认

手册常要写"某操作有 / 无二次确认"。**无二次确认的按钮点下去就是既成事实**，不能试。判定顺序：

1. **读前端 bundle 找确认组件** —— 搜该按钮文案附近的 `Popconfirm` / `Modal.confirm` / `Modal.confirm(`。找到 → 有确认；没找到 → 大概率**直接执行**。
2. **在自建对象上实测** —— 造一个测试对象推到该状态，点，观察。**这是唯一可靠证据**。
3. **两者都做不到** —— 不写"有/无确认"，改写成"点击后…"的中性描述，或在报告中标注**该项未验证**。**绝不靠"一般都有确认"来填。**

## 七、输出：按钮矩阵表

清点结果整理成**按钮矩阵表**——它同时是手册素材和复查断言来源。

**主表（按状态分行）：**

| 方案状态 | 「操作」列按钮 | 能做什么 |
|---|---|---|
| 草稿 | 编辑 / 发布 / 删除 | 方案还没启用，可继续改；发布后才能用来建任务 |
| 已发布 | 查看 / 片段标注配置 / 创建任务 / 归档 | 内容已锁定不能改，只能查看、配标注、建任务或归档 |
| 已归档 | 查看 / 片段标注配置 / 删除 | 已归档，不能再建任务；只能查看或删除 |

**表外单列（无文字图标，因为不在按钮文字里，表格列不出来）：**

> 「操作」列**最左侧**有一个**不带文字的图标按钮**，鼠标悬停显示「创建副本」，**三种状态都有**。

**写法要求**：见 `manual-style.md` 的「表格优先原则」「可读性三原则」——术语用界面原名、一句一概念、每行补"能做什么 / 为什么"。

## 八、接进流程

按钮穷举不是独立一环，它**嵌在阶段一，服务于阶段二写作与阶段四复查**：

| 阶段 | 怎么用它 |
|---|---|
| **一 · 探查** | 每个新页面按[第二节](#二清点范围一个页面扫哪些位置)扫 9 处，逐态记录，产出按钮矩阵表 |
| **二 · 写作** | 矩阵表直接落成手册的「状态 → 可用操作」表；无文字图标**必须**在表外单独成句（表格列不出） |
| **三 · 校验** | 核对手册表格的行数 = 实机状态数；每个状态列出的按钮与矩阵表逐项对上 |
| **四 · 复查** | 矩阵表**逐行变断言**：每个按钮 = 存在性 + 位置 + 可用态 + 点击结果，4 条断言。**"仅某状态有"的限定必须逐态实测** |
| **五 · 发布** | 按钮描述有变更 → 重跑结构校验与复查，不留旧描述 |

> 复查环节的按钮断言分类见 `audit-playbook.md` 的「断言分类清单」。

## 九、实战发现（真实案例）

以下是穷举法在真实平台上翻出来的偏差，全部是"不点就发现不了"的类型：

1. **「创建副本」图标位置与范围全错** —— 手册写"行末、仅已发布"，实测在**操作列最左侧**、**三种状态都有**。
2. **方案三态漏了第三态** —— 手册只写草稿/已发布，实测有**已归档**，且归档后按钮集是"查看 / 片段标注配置 / **删除**"（没有创建任务）。
3. **【创建任务】不是即时生效** —— 手册要写清它"打开「新建采集任务」抽屉并把方案预填好"，而非直接建出任务。
4. **【归档】有二次确认** —— 确认框原文：「确认将方案「XXX」归档？归档后不可再创建任务。」
5. **【停用】无二次确认、点下即生效** —— 数字标签类的停用开关没有确认框（曾因此误停真实触发器）。
6. **确认框按钮文案带空格** —— 是「删 除」「确 定」，不是「删除」「确定」；脚本匹配要用宽松正则。
7. **卡片菜单的禁用态** —— 项目卡片菜单 5 项，其中【归档】【删除】在特定状态下**置灰不可点**——这层信息不点开菜单根本看不到。

**共同点：全是"看一眼就以为懂了"的地方。**
