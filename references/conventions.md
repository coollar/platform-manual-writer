## 一、文件与目录布局

推荐布局（按项目实际调整，但**同类资产集中放**）：

```
<项目>/
├── outputs/
│   ├── <detail>_folder/
│   │   ├── draft.xml            # 详细版源文件
│   │   └── *.png                # 详细版配图
│   ├── simple/
│   │   └── draft_simple.xml     # 简版源文件
│   ├── *.js                     # 探查 / 复查脚本
│   ├── *.py                     # 编辑 / 校验脚本
│   ├── state.json               # 登录态（storageState）
│   └── vf/                      # 复查证据：截图、日志、DOM dump
└── .workbuddy/memory/*.md       # 跨会话接续信息
```

**要点**：
- 图片放**与源文件同目录**，`<img path="@./<folder>/x.png">` 用相对路径，推送时 cwd 在 `outputs/`。
- 登录态 `state.json`、证据 `vf/`、脚本与源文件**分开**，便于清理与复用。

## 二、版本号规范

| | 简版 | 详细版 |
|---|---|---|
| 版本序列 | **V1.x** | **V2.x** |
| 递增 | 每次**实质改动** +0.1（V1.11 → V1.12） | 同 |
| 落点 | 正文顶部**版本行** | 文档信息表「手册版本」单元格 |

**版本行写法**：`<p><b>V1.12</b>｜覆盖 <模块清单> ｜详细版</p>`
**详细版版本单元格**：`V2.9（一句话变更说明）`

**规则**：
- 简版与详细版**各自独立递增**，不要求号段对齐。
- 纯错字修正可不升版本；**改了内容（增删句子 / 补表格 / 改事实）就升**。
- **模块清单三处必须一致**：`<title>`、版本行/版本单元格、正文 H1 实际顺序。

## 三、备份规范

**每次改动前先备份**，命名 `<源文件名>_v<N>_backup.xml`，其中 **N = 改之前的版本号**。

```
改前 V2.8  →  备份 draft_v28_backup.xml  →  改后 V2.9
改前 V2.9  →  备份 draft_v29_backup.xml  →  改后 V2.10
```

**规则**：
- **不覆盖旧备份**，保留全部历史，可逐级回滚。
- 备份与改动**同一次操作**完成（脚本里先 `cp` 再写）。
- 推送前的最终源文件也应有一次备份。

## 四、图片目录与命名

- **目录**：与源文件同目录（`outputs/<doc>_folder/`）。
- **命名**：`<模块前缀><两位序号>_<语义>.png`
  - 例：`fb01_dashboard.png`（fb=真机回流）、`g13_dl_items.png`、`s13_plan_list.png`
  - 前缀小写、语义化，同模块内序号连续。
- **图注**：`caption="图 N  简短说明"`，说明写"这张图能看到什么"。
- **一图一义**，不堆叠；关键区域用 `scripts/capture_lib.js` 加红框 + 圆形序号。

## 五、脚本与证据

- **探查/复查脚本**统一放在 `outputs/`，命名能自解释（`probe_xxx.js`、`verify_xxx.js`、`write_xxx.js`）。
- **编辑脚本**命名 `fix_<主题>_v<N>.py`，与版本号对应。
- **证据留存**：每个脚本输出**重定向到日志文件**（`> vf/xxx.log 2>&1`），不要用 `| head` 管道（会 SIGPIPE 杀 node 进程）。
- 截图、DOM dump、接口返回统一放 `vf/`，作为复查与争议时的对证材料。

---

## 六、测试数据命名

- 闭环验证的自建对象，**名称带明显前缀**（如 `ZZTEST_`），一眼可辨、便于全平台搜清理。
- **用完即清**，最后按前缀全平台扫一遍残留。
- **归档后未必能删** —— 制造已归档对象前，先确认删除入口可用。

---

## 命名一览

| 资产 | 规范 | 例 |
|---|---|---|
| 详细版源文件 | `draft.xml` | — |
| 简版源文件 | `draft_simple.xml` | — |
| 备份 | `<name>_v<N>_backup.xml` | `draft_v28_backup.xml` |
| 配图 | `<前缀><序号>_<语义>.png` | `fb01_dashboard.png` |
| 探查脚本 | `probe_<模块>*.js` | `probe_createtask.js` |
| 复查脚本 | `audit_template.js` 派生 | `verify_simple.js` |
| 编辑脚本 | `fix_<主题>_v<N>.py` | `fix_plan_archive_v29.py` |
| 测试数据 | `<前缀>_名称` | `ZZTEST_方案A` |
