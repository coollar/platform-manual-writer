## 一、探查总原则

1. **只读优先** —— 默认只打开抽屉/弹窗/下拉、dump 内容，不点保存/删除/停用/归档。
2. **先读源码再动手** —— 状态变更类按钮（发布/启用/停用/归档）先确认它是不是「直接执行、无二次确认」。读前端 bundle 或观察代码，比点下去再后悔安全得多。
3. **界面里没写死的，都不能凭推断写** —— 这是写作红线在探查阶段的落法：没看见的枚举值、没展开的选项、没触发的提示，一律不写。
4. **探查是为了写手册** —— 目标不是穷举系统，而是拿到"手册需要描述的那些交互"的事实。按章节需求定向探查，不做无目的漫游。
5. **按钮要穷举** —— "定向探查"不等于"扫一眼"。**页面上每个可点元素都要翻出来记一笔**，尤其是无文字的、悬停才出的、藏在菜单里的、禁用的。详见[第五节](#五按钮穷举)。

## 二、登录与登录态

### 登录

用 `scripts/login.js`（参数化）：

```bash
MANUAL_LOGIN_URL="https://<平台>/login?redirect=%2F" \
MANUAL_USER="<账号>" MANUAL_PASS="<密码>" \
NODE_PATH="<node-workspace>/node_modules" \
<node> scripts/login.js
```

产出 `state.json`（Playwright storageState），后续所有脚本 `newContext({ storageState: 'state.json' })` 复用。

### 登录态排查（重要）

登录态会过期，表现为**页面被踢回登录页 / 列表空白**。排查顺序：

| 症状 | 排查 | 结论 |
|---|---|---|
| 页面跳登录页 | 看 JWT 的 `exp`（解码 payload，不验签） | `exp` 已过 → 重新登录 |
| `exp` 未过期但仍被登出 | 抓鉴权接口（如 `get-user-permissions`）的状态码与响应体 | 返回 **400 + "账号已在其他地方登录"** → 平台**单点互斥**，你的会话被顶掉了，必须重新登录 |
| 登录报错 | 核对账号密码、是否需要验证码 / 扫码 | — |

**单点互斥的坑**：多数内部平台不允许同一账号多端并存。自动化用 A 账号时，若有人用 A 账号在别处登录，你的会话会失效。**解决办法**：换一个专用账号，或请对方在你跑脚本期间不要登录。

**令牌可能藏在 localStorage**（如 zustand persist 的 `xxx_search_global`，token 在 `state.user.access_token`）。拿到合法 token 后也可直接注入复刻会话，避免互斥。

## 三、建立平台地图

1. **顶部导航 / 侧边菜单** —— 先点一遍，列出所有一级模块与其对应页面。
2. **页面层级** —— 记录"列表页 → 详情页 → 子 Tab"的进入路径，**只用界面语言描述**（左侧菜单名、Tab 名），不要落到 URL。
3. **权限接口** —— 若有 `get-user-permissions` 之类的接口，一次调用即可拿到**全菜单树 + 权限动作码**，比逐页点击完整得多，值得优先抓取。
4. **前端 bundle（可选，进阶）** —— 现代 SPA 会把路由、接口、UI 文案、权限码、状态枚举全打包进 JS 分片。下载主 bundle，grep 分片名与 `/views/...` 路径，再下载相关分片 grep 接口路径与中文字串，可**离线还原**整个模块结构，且比逐页点击更完整。适合需要穷举枚举值的场景。

## 四、页面元素定位范式

平台多用 Ant Design / Element 等组件库，定位时有固定套路：

### 表格

```js
// 取第一个数据行（注意：首行常是测量行 ant-table-measure-row，须过滤）
const row = page.locator('.ant-table-tbody tr.ant-table-row').first();
// 行末操作列
const ops = row.locator('td:last-child');
// 若表格有勾选列，列序会偏移，操作列不再是 last-child —— 先 dump 全部 td 的文本再定位
```

### 勾选框

Ant 的 checkbox 是自定义控件，`locator.check()` 常报 "Clicking the checkbox did not change its state"。改用点击该行的复选框单元格或 `.ant-checkbox-wrapper`。

### 点击被遮挡

抽屉/固定列/浮层会拦截点击，报 `subtree intercepts pointer events`。改用坐标点击 `page.mouse.click(x, y)`。

### 下拉 / 级联

- 普通下拉：点开 → 读 `.ant-select-dropdown .ant-select-item-option` 文本枚举。
- **级联选择器（cascader）**：点开 → 一级菜单 `.ant-cascader-menu` 选一级 → 展开二级菜单选叶子。**用坐标点击展开**比 `force click` 可靠。
- **关闭下拉别按 Esc** —— 在抽屉里按 Esc 可能把整个抽屉关掉。改为点抽屉标题或空白处。

### 「展开」类控件不一定是 button

筛选区的「展开 ∨」可能不是 `<button>`，用 `text=展开` 选择器点不到。改用**可见性判断**：先记录可见筛选项数，点击后对比是否增多。

### 切 Tab 后的 DOM 残留

切换 Tab 后 `querySelectorAll('.ant-table-tbody tr')` 可能读到旧表。取**最后一个** wrapper，或等新表出现再读。

### 按文本定位要加尺寸约束

同名文本会命中左侧导航。用 `{ txt, minW, maxW, minH, maxH }` 约束容器尺寸，取满足条件的**最小**容器。

## 五、按钮穷举

**这是探查里最容易被跳过、也最容易出事的一步。** 手册漏写的内容有固定规律——全是"不点就看不见"的按钮：无文字纯图标（如「创建副本」）、悬停才出现的、藏在「…」菜单里的、只在某些状态下出现的、禁用的、抽屉底部的。

**动作**：

1. **自动扫一遍** —— 跑 `scripts/inventory_buttons.js`，它会列出页面上所有 `button / a / [role=button] / .anticon`（含无文字、禁用、几何位置），并对无文字图标逐个悬停读 tooltip。产 `buttons.json` + 截图。
2. **补扫自动扫不到的** —— 菜单 / 抽屉 / 弹窗里的按钮需点开才可见，用脚本内 `dumpAfterClick(selector, label)` 手动补扫；折叠区先展开再扫。
3. **逐状态各扫一遍** —— 任何"仅某状态有 / 三种状态都有"的说法，都要把对象推到每个状态分别扫，不能拿一条现成数据推断。
4. **归类记字段** —— 位置 / 文案或图标+悬停提示 / 出现在哪些状态 / 是否禁用 / 点击结果 / 有无二次确认 / 可逆性 / 危险级 / 证据。
5. **整理成按钮矩阵表** —— 直接作为手册的「状态 → 可用操作」表，同时是复查断言的来源。

**铁律：不要靠图标形状猜含义**，必须悬停看提示或点开看结果；**无文字图标按钮要单独成句**（表格里列不出来）。

完整方法（清点范围 9 处、字段表、点击分级、高危判定、矩阵表格式、实战发现）见 `references/button-inventory.md`。

## 六、安全规范与事故教训

> 这几条是拿生产事故换来的，逐条遵守。

### 高危按钮清单

| 类型 | 风险 | 处置 |
|---|---|---|
| **发布 / 启用 / 停用** | 常**无二次确认、点下即生效**，且可能**无反向入口** | 点前读源码确认；不确定就不点 |
| **归档** | 终态、不可逆 | 必须二次确认才可点（确认框通常有） |
| **删除** | 数据消失 | 只用自建测试数据 |
| **重新质检 / 转码 / 播放** | 触发计算或覆写 | 不点 |

### ⚠️ 真实事故（务必吸取）

1. **TRG-26 停用事故**：探查「停用是否有二次确认」时，点了真实触发器。该按钮**即时生效、无确认**，导致线上对象被停用，事后靠脚本才恢复。**数字标签类的停用开关往往没有确认框。**
2. **任务发布事故**：核对"任务发布是否有二次确认"时点了「发布」，该按钮**直接执行**，把测试任务由草稿变已发布，且平台**无取消发布入口**。
3. **残留测试对象**：闭环验证中因确认框按钮文案是「删 除」而非「确 定」（注意中间有空格），脚本没点中，残留了测试对象。**务必扫残留。**

**共同教训**：凡状态变更类按钮，**先确认交互形态（有无 Popconfirm / Modal.confirm），再决定要不要点**。宁可写得保守，也不冒险点生产对象。

### 脚本健壮性

- 确认框按钮文案可能带空格（Ant 对两字按钮会插空格），匹配时用宽松正则或 `:has-text("删")`。
- 别用 `| head -N` 管道接 node 输出——会触发 SIGPIPE 杀进程。改为重定向到日志文件再读。

## 七、写操作闭环验证

> 说明：探查阶段的写闭环（本节）用于**拿到写作素材**；手册**写完后对成品的系统性复查**见 `references/audit-playbook.md`（那里要求覆盖所有状态、逐条 PASS/FAIL）。

当手册需要断言"某操作能成功 / 某状态可切换"时，在**获得授权**后做闭环。

**标准闭环**（对每个可逆对象）：

```
① 新建（用带前缀的测试名，如 ZZTEST_xxx）
② 保存
③ 验证入列（列表/详情出现该对象）
④ 观察目标交互（确认框文案、状态变化）
⑤ 删除
⑥ 复查消失
```

**规则**：

- **测试数据必带明显前缀**（如 `ZZTEST_`），一眼可辨、便于清理。
- **用完即清**，最后**扫一遍全平台残留**（按前缀搜）。
- **归档后未必能删** —— 先验证删除入口是否可用；若不能删，**不要制造已归档对象**。
- **不可逆动作只在自建对象上做**，绝不在真实业务数据上做。

## 八、证据留存

- **截图**：每张存盘并编号，作为写作与复核证据。用 `scripts/capture_lib.js` 加红框 + 圆形序号。
- **持续重绘的 canvas 页面（3D / 视频 / 播放器 / 可视化看板）截图有坑**：
  1. Playwright 的 `page.screenshot()` 会等"渲染稳定"，canvas 一直重绘 → **等不到，30s 超时**。改用 CDP 直取：
     ```js
     const cdp = await ctx.newCDPSession(page);
     const r = await cdp.send('Page.captureScreenshot', { format: 'png' });
     fs.writeFileSync(path, Buffer.from(r.data, 'base64'));
     ```
  2. headless 下要能出画面，启动参数加 `--enable-unsafe-swiftshader --use-gl=angle --use-angle=swiftshader`，否则面板一直空白/加载中。
  3. 这类页面**加载慢**：要轮询等到"加载中"遮罩与占位文案（如「等待图像消息中」）**都消失**再截，否则截到空面板（实测约 45s）。
  4. 想露出被折叠/遮挡的区域，先做**只读 UI 操作**（如点折叠头收起上层区块）再截，别为截图去触发业务动作。
- **窄侧栏面板单独出图：用「当次会话 CSS 浮层」放大**。现代后台（Ant Design / MUI）的右侧信息面板往往只有 200~300px 宽，而里面的表单比面板还宽被裁；直接截必然看不清，读者会以为"没截到"。做法是注入 CSS 把它临时放大到视口左上角（**不改平台数据、不改布局配置，关页即恢复**）。四条硬约束（踩过才知道）：
  1. **选择器必须用属性匹配**。MUI/emotion 生成的类名带 hash（如 `mui-1hoembp-accordionContainer`），**每次页面加载都会变**——写死类名的 CSS 会静默失效（表现为"宽度好像生效了、定位却没生效"）。用 `[class*="accordionContainer"]` 这类属性选择器。
  2. **给承载窗口提层，否则点击全被拦截**。浮层若在 Mosaic / GridLayout 这类布局容器的层叠上下文里，会被兄弟面板盖住：`z-index` 再高也没用，Playwright `click()` 会一直 30s 超时。补一句 `.mosaic-window:has(你的容器){z-index:9999970}` 即可。
  3. **上移容器时必须同步增高**。想让第 N 个折叠块顶到视口顶部，写 `top: -offset` 后容器**下边界也会上移**，只剩一小条可见（现象：图上半截正常、下半截直接穿透看到别的内容）。要同时 `height: 视口高 + offset`。
  4. **不要动 DOM 结构**。`document.body.appendChild(容器)` 会与 React 重建冲突，之后**所有点击失效**；`display:none` 切换折叠块会让折叠动画态下的文字不渲染（现象：红框都在、字全没了）。控制展开就用点击。
  5. 展开/收起控制要**双策略 + 收敛校验**：原生 `element.click()` 和 Playwright `click()` 往往**各对一半区块有效**（有的折叠头被标题栏拦截、有的被浮层遮挡），写循环按 `aria-expanded` 校验并交替尝试，别只试一次。
  6. 面板内容总高常超过视口（例如 5 个折叠块展开共 2100px，面板可视仅 590px）：**不要试图全部塞进一张图**，按目标区块分别出图。
- **红框 + 圆形序号标注**：用 `scripts/capture_lib.js` 的 `mark()`，或自注入 `position:fixed; z-index:2147483000` 的 div 覆盖层（红色 `#FF3B30`、圆角 6px、序号在框左上角外侧 12px）。要点：
  - 测量坐标要**限定在所属区块内**查询（`acc.querySelectorAll('*')` 而不是整个面板），否则同名字段（如「验收结论」）会跨区块误匹配到别的位置。
  - **区块顶部留 28px 空隙**，否则序号圆圈会压住标题首字（看起来像错字）。
  - 面板特写这类竖图建议用 CDP 的 `clip.scale: 2` 出 2 倍图，再按与其他图相同的缩放比放进文档，否则放大后发虚。
- **字段 dump**：把抽屉/弹窗的字段、枚举、只读态 dump 成 JSON，写作时直接查。
- **日志**：每个探查脚本输出重定向到日志文件，便于回溯。

有了证据，任何"手册与系统不一致"的争议都能当场对证。
